# ShaderCalc (agent notes)

WPF worksheet for checking HLSL / C++ shader maths: a custom HLSL interpreter, with DXC + D3D12 WARP as the
bit-exact reference. Started 2026-10-07 as KalkGui (a kalk front end); kalk was replaced by the interpreter and
the repo renamed on 2026-10-08 (GitHub `gaetan-deturche/ShaderCalc`). Only `third_party/kalk/units.kalk` is left
of kalk, kept for the planned full unit table.

## Layout

- `src/ShaderCalc.Core` (net9.0, no UI, namespaces `ShaderCalc.*`): interpreter, worksheet engine, reference
  runner, docs.
- `src/ShaderCalc.App` (net9.0-windows, exe `ShaderCalc`, WPF + AvalonEdit 6.3, Fluent `ThemeMode.System`).
  Code-behind, no MVVM.
- `tests/ShaderCalc.Tests`: interpreter, language, worksheet, docs, reference and conformance tests (294).

## Interpreter pipeline (Core)

`Lexer` → `Preprocessor` (one shared instance across worksheet files) → `Parser` → `Binder` (static types,
overloads, conversions, a typed bound tree) → `Evaluator` (every component is raw `ulong` bits plus a `UnitTag`).

- Unsuffixed literals are DXC's `literal int` / `literal float` (64-bit) until they meet a type.
- Intrinsics (`Evaluation/Intrinsics.cs`) follow DXC's lowering as read from `-Gis` disassembly: e.g. `pow(x, 2)`
  with a constant 2 is `x*x`, otherwise `exp2(log2(x) * y)`; `smoothstep` is `t*(t*(3-t*2))`.
- `SemanticsProfile` holds every point where HLSL implementations disagree. The default (`Hlsl`) is what WARP
  does: ties-to-even, masked shift counts, unfused mad, denormal flush on input and output, `f32tof16` toward
  zero, float `%` from the quotient, signed `/0` = INT_MAX, `uint`→`float` via signed. A Slang-CPU profile and a
  UI switch for it are planned.
- Units: `Units/Dimension.cs` (small SI table for now); `UnitChecker` reports mismatches without stopping.

## Worksheet (`Worksheet.Evaluate`)

- All tabs are one program in tab order. Declarations are hoisted; top-level lines run in order.
- A newline ends a top-level statement unless a bracket is open (`Parser.AtLineBreak`).
- A top-level variable (declared, or `x = v` for a new name) is a global that functions can read.
- Each line gets its own `Evaluator` over shared storage, its own diagnostics, and a snapshot of the globals it
  starts from (`LineResult.Inputs`, used by the reference). A line with bind errors isn't run.

## Reference (`Reference/`)

- `WarpDevice`: DXC (Vortice.Dxc) → signed DXIL → compute dispatch on WARP. `dxil.dll` is preloaded because
  dxcompiler loads it by name from the exe folder only. `RunCached` caches by source and inputs.
- `ReferenceChecker` emits a harness around the line. Uniforms, globals and session variables come from an input
  buffer, and the line's own literals are replaced by buffer loads, so DXC can't constant-fold the line.
  `Intrinsic.ConstantSensitiveArguments` keeps arguments like `pow`'s exponent literal (DXC lowers a constant 2
  differently). The substitution applies only while emitting the line (`_isEmittingLine`), never function bodies.
- Verdicts: bit-identical `✓`; `≈` for approximate intrinsics within 64 ulp or 0.0008 absolute; `≠` otherwise.
- `Conformance.cs` sweeps an expression over special and random inputs in one dispatch. Set
  `SHADERCALC_CONFORMANCE_DUMP=<file>` to write the reports.

## App

- `Services/WorksheetStore`: every `*.hlsl` in `~/.shadercalc` (or `SHADERCALC_DATA_DIR`) is a tab. `state.json`
  holds the tab order, the active tab and the window placement. Writes go to a temp file and are moved into place. Delete sends the file
  to the Recycle Bin. A `FileSystemWatcher` reloads outside edits.
- `Services/EvaluationController`: 200 ms debounce, cancellation, evaluation off the UI thread, then a reference
  queue with the active tab first.
- `Ui/WorksheetView`: the editor plus `ResultColumn`, which is aligned to AvalonEdit's visual lines and has a UIA
  peer (ItemStatus = "line mark text"). Also squiggles, hover tips and completion.
- `Ui/Inspector`: type, units, per-component value/hex/bits, problems, the reference verdict and the emitted HLSL.
- Docs: `Core/Docs/reference.md` (embedded) has the topics plus one `## name` page per intrinsic; the signature
  line is formatted `` `sig` · kinds ``. `DocumentationTests` checks that the pages and the intrinsic table match.
- Keys: F1 docs for the word at the caret, F2 rename, Ctrl+T new tab, Ctrl+S save, Esc focuses the editor.
- Icon: `Assets/shadercalc.{png,ico}` generated by `Claude/make-icon.ps1` (gitignored).

## Build / test

- `global.json` pins SDK 9.0.308 with `rollForward: disable` (this machine's 9.0.312 can't run).
- `dotnet build ShaderCalc.sln` (0 warnings), `dotnet test tests/ShaderCalc.Tests`.
- The single-file publish command is in README.md. It was verified on 2026-10-08: DXC + WARP work from the
  self-extracted native DLLs. The exe is ~190 MB.

## UI testing: hidden desktop only (never steal the user's focus)

Shared memory `no-focus-steal-gui-testing` has the rule. The tooling is in `Claude/` (gitignored):
- `run-hidden.ps1 -SpecPath Claude\scenarios\<x>.json` creates the `ShaderCalcTest` desktop and runs the driver
  there. A watchdog kills the run if ShaderCalc shows up on the user's desktop.
- `ui-drive.ps1` runs a JSON list of steps: `launch` (`files` seeds the data folder, `exe` picks another build),
  `setEditor`, `typeEditor`, `caret`, `key`, `wait`, `set`, `invoke`, `invokeName`, `selectTab`, `selectDoc`,
  `read`, `tabs`, `find`, `windows`, `snapshot`, `expect`, `waitFor`, `writeFile`, `expectFile`, `desktop`,
  `close`. Exit code 1 on any failure.
- Scenarios: `smoke` (results, reference, inspector, F1), `worksheet` (shared tabs, ≠ line, error line, outside
  edit, new, rename, completion, delete), `publish-smoke` (the published exe). All pass as of 2026-10-08.
- Test hooks: `SHADERCALC_DATA_DIR` isolates runs from `~/.shadercalc`. `SHADERCALC_AUTOMATION=1` (Debug builds
  only) enables the `WM_COPYDATA` snapshot hook (`Ui/AutomationSnapshot.cs`), the only way to capture the hidden
  desktop.
- Focus on the hidden desktop: posted keys work (no modifiers), and UIA SetFocus is refused. The driver focuses the
  editor with Esc. A Win32 MessageBox button has no InvokePattern, so `invokeName` falls back to BM_CLICK on its HWND.
